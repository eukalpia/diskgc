## لماذا

تمتلئ أقراص المطورين بأشياء لم يطلب أحد الاحتفاظ بها: مجلدات Cargo `target/` التي تنمو 100 GB في يومين، و`node_modules` للفروع التي هُجرت في يوليو، وذاكرات Go المؤقتة التي تُعاد تعبئتها مع كل تشغيل للاختبارات، والحاويات التي تتركها الاختبارات المتوقفة، والمجلدات المؤقتة لأدوات البرمجة بالذكاء الاصطناعي. يطلق macOS على كل ذلك اسم "System Data" ولا يقدّم أي مساعدة، و`du` يخبرك *أين* توجد المساحة، لا *ما الذي يمكن حذفه بأمان*.

يعمل diskgc كعملية خلفية صغيرة (daemon)، تراقب المساحة الحرة واتجاهها، وتزيل فقط ما يمكن للأداة إعادة إنشاءه، مع سبب مكتوب لكل إجراء، وخطة يمكنك قراءتها قبل أي تنفيذ، وسجل بما تم تحريره.

## أبرز الميزات

- **يشرح نفسه.** لكل إجراء سبب، مثل: *"target بحجم 105 GB (أكبر من الحد 40 GB): كل ما هو أقدم من يوم"*، و*"المشروع لم يُمسّ منذ 30 يومًا؛ يُستعاد عبر install"*.
- **يعرف المشاريع لا المجلدات فقط.** يُعثر على `target/` من خلال محتواه، ولا تُعتبر مجلدات البناء إلا بجوار علامة المشروع الخاصة بها، ويُقيَّم النشاط على مستوى المشروع كله (شجرة العمل git worktree تُعد مشروعًا مستقلًا).
- **يتصرف قبل امتلاء القرص.** يتنبأ بالمساحة الحرة خلال الساعات الست الأخيرة ويصعّد التنظيف مسبقًا، وتشتد العتبات تدريجيًا من *عادي* إلى *منخفض* ثم *حرج*.
- **لا يمسّ ما يهم.** الشيفرة المصدرية و`.git` وقواعد البيانات وسجلات المحادثات لا تُعد مرشحة للحذف أبدًا، والأنماط glob المستثناة لا تُمسّ، والسجلات تُضغط في مكانها ولا تُحذف.
- **يكشف السبب الجذري.** يعرض `diskgc stats` النمو يوميًا ولكل فئة، والمسارات التي تعود باستمرار، وهي الأماكن التي ينبغي إصلاحها لا تنظيفها فقط.
- **لوحة طرفية وJSON.** واجهة TUI من ست شاشات، وخيار `--json` في كل أمر للسكربتات.

## البداية السريعة

```sh
cargo install --locked --git https://github.com/eukalpia/diskgc diskgc
diskgc config --edit      # اضبط [scan] roots على المكان الذي توجد فيه مشاريعك
diskgc plan               # ما الذي سيحذفه التنظيف، ولماذا، ولن يُمسّ شيء
diskgc install            # شغّل العملية الخلفية عند تسجيل الدخول (launchd / systemd --user / جدولة المهام)
diskgc status
```

تتوفر ملفات ثنائية جاهزة للتشغيل لـ macOS (Apple Silicon وIntel) وLinux (x86_64) وWindows (x86_64) ضمن كل [إصدار](https://github.com/eukalpia/diskgc/releases). فُكّ ضغط `diskgc` (واختياريًا `diskgc-ui`) في أي مجلد ضمن `PATH` لديك.

## ما الذي ينظّفه

| القاعدة | المحتوى | التوقيت |
|------|------|------|
| مجلدات Rust target | مجلدات `target/` (تُعثر عليها حسب المحتوى أينما كانت) | مخرجات البناء لم تُمسّ لمدة 7 أيام؛ فوق 20 GB تُحذف أيضًا كاشات الزيادة والملفات التنفيذية الكبيرة للاختبارات؛ فوق 40 GB يُحذف كل ما هو أقدم من يوم؛ وميزانية 40 GB لجميع مجلدات target معًا |
| node_modules | `node_modules` بجوار `package.json` | لم يتغير شيء في المشروع لمدة 30 يومًا |
| مجلدات البناء | `.dart_tool`، و`build`، و`_build`، و`.next`، و`.turbo`، و`__pycache__`، و`.gradle`، وغيرها، بجوار علامة مشروع | القاعدة نفسها: 30 يومًا |
| المجلدات المؤقتة | مجلدات Claude Code المؤقتة لكل جلسة، وإدخالاتك الخاصة في مجلد الملفات المؤقتة للنظام، ومجلدات العمل المتقادمة في `$TMPDIR` الخاص بالمستخدم (macOS) | خاملة لمدة 3 أيام / 7 أيام / 24 ساعة |
| أدوات الذكاء الاصطناعي | إصدارات تطبيق Codex القديمة، وتثبيتات وقت التشغيل المهجورة | دائمًا (يُبقي الحالي + 1) |
| Docker | حاويات testcontainers اليتيمة، والحاويات المتوقفة، والأحجام والصور المعلّقة، وكاش البناء | 2 ساعة / 24 ساعة / 7 أيام |
| كاشات الأدوات | كاشات Go وnpm وuv وpnpm وsccache التي تتجاوز الحد، وبقايا تحديثات Chrome وVS Code، وتنزيلات Homebrew، وXcode DerivedData، وكاشات المحاكي وMetal shader | حدود لكل قاعدة |
| الملفات الباردة | سجلات الجلسات وسجلات JSONL الخاصة بـ Codex وClaude Code | **مضغوطة** بواسطة نظام الملفات (APFS وNTFS)، ولا تُحذف أبدًا |

## كيف يقرر

يستيقظ الـdaemon كل 10 دقائق وينظر إلى المساحة الحرة:

| المساحة الحرة | السلوك |
|------------|------|
| أعلى من `comfortable_gb` (150) | تنظيف مجدول كل 6 ساعات |
| أقل من `comfortable_gb` | تنظيف فوري بالنوافذ الزمنية العادية |
| أقل من `low_gb` (100) | مستوى *منخفض*: تُقسم جميع نوافذ التقادم إلى النصف |
| أقل من `critical_gb` (60) | مستوى *حرج*: تُقسم النوافذ على أربعة، وتُقسم حدود الحجم إلى النصف |

تتنبأ ملاءمة المربعات الصغرى (least-squares) على لقطات الساعات الست الأخيرة بالمساحة الحرة بعد 24 ساعة، فإذا تجاوز التوقع عتبة ما، يصعّد الـdaemon مسبقًا. يُسجَّل كل تشغيل، لذا يعرض `diskgc stats` النمو يوميًا ولكل فئة، والمتكررين المخالفين.

## الأمان

يحذف diskgc الملفات، وهذه مهمته، لذلك صُمّم ليكون متوقعًا:

- يقترح فقط ما يمكن للأداة إعادة إنشاؤه (مخرجات البناء، ومجلدات الاعتماديات، والكاشات، والملفات المؤقتة) ويعطي سبب كل إجراء. يعرض `plan` و`clean -n` هذه القائمة بالضبط دون أن يمسّا أي شيء.
- الشيفرة المصدرية و`.git` وقواعد البيانات وسجلات المحادثات لا تُعد مرشحة أبدًا، وأي شيء يطابق `[scan] exclude` لا يُمسّ، والمنفّذ يرفض أي مسار خارج `[safety] allowed_prefixes` (افتراضيًا مجلد المنزل ومجلدات الملفات المؤقتة والكاش في النظام).
- `[safety] delete_mode = "trash"` ينقل الأشياء إلى سلة المهملات بدل حذفها نهائيًا (على macOS وLinux؛ وإذا كانت السلة على وحدة تخزين أخرى يعود إلى الحذف).
- يُسجَّل كل تشغيل (`diskgc history`) مع ما خُطط له وما حُرّر فعلًا.

يعمل البرنامج دون مراقبة بصلاحياتك، لذا اقرأ أول `plan` على جهازك قبل تثبيت الـdaemon.

## لوحة الطرفية

يفتح `diskgc ui` لوحة تحكم مبنية باستخدام [Cinder](https://github.com/eukalpia/cinder) تتواصل مع الـdaemon عبر [بروتوكول IPC](../PROTOCOL.md):

| الشاشة | |
|--------|---|
| **نظرة عامة** | المساحة الحرة، والمستوى، والتنبؤ، وأين تذهب المساحة |
| **الخطة** | كل إجراء مقترح مع سببه: ألغِ تحديد ما يجب إبقاؤه، ونفّذ الباقي، أو شغّل محاكاة |
| **التقرير** | أكبر المتسببين لكل فئة |
| **المحفوظات** | عمليات التشغيل، والنمو يوميًا، والمتكررون المخالفون |
| **الذاكرة** | استهلاك الـRAM حسب البرنامج، وعمليات المساعدة اليتيمة |
| **السجل** | نشاط الـdaemon المباشر |

```
1-6 / tab   switch screens        r   refresh the current screen
p           build a plan          space / enter   toggle the highlighted action
x           execute selected      n   dry run             a   toggle all
k           terminate orphaned helper processes (Memory)   q   quit
```

اللوحة ملف تنفيذي أصلي مستقل (`diskgc-ui`). يبحث عنه `diskgc ui` بجوار `diskgc` أو في `PATH`، ويشغّل الـdaemon إذا لم يكن يعمل.

## الأوامر

```
diskgc report            ما الذي يشغل القرص: الفئات وأكبر المتسببين
diskgc plan              ما الذي سيفعله التنظيف، مع الأسباب، دون المساس بأي شيء
diskgc clean [-n]        التنظيف الآن (-n = الخطة فقط)
diskgc status            حالة الـdaemon، والمساحة الحرة، والتنبؤ، وآخر تشغيل
diskgc stats             النمو يوميًا، واتجاهات الفئات، والمتكررون المخالفون
diskgc history           آخر عمليات التشغيل وما حرّرته
diskgc mem               استهلاك الذاكرة حسب العملية، وعمليات المساعدة اليتيمة (--kill-orphans)
diskgc install | uninstall
diskgc config [--edit|--show]
diskgc ui                لوحة الطرفية
```

كل أمر يقبل `--json`.

## الإعدادات

`~/.config/diskgc/config.toml` (Linux وmacOS) أو `%APPDATA%\diskgc\config.toml` (Windows)، يُنشأ بالقيم الافتراضية عند أول تشغيل، ويعيد الـdaemon قراءته في كل دورة. يُشرح كل مفتاح في [docs/CONFIG.md](../CONFIG.md). وهذه أهم الإعدادات:

```toml
[scan]
roots = ["~/work", "~/src"]          # المكان الذي توجد فيه مشاريعك
exclude = ["~/work/keep-forever/**"] # أنماط glob لا يحق لأي قاعدة أن تمسّها

[thresholds]
comfortable_gb = 150
low_gb = 100
critical_gb = 60

[safety]
delete_mode = "permanent"            # أو "trash"
```

## المنصات

| المنصة | الحالة |
|----------|--------|
| macOS (APFS) | مستخدم يوميًا، وهو الهدف الرئيسي |
| Linux | مُختبر في CI وفي الحاويات؛ تشغيل تلقائي عبر `systemd --user` |
| Windows | يُبنى وينجح في الاختبارات على CI؛ التشغيل التلقائي عبر Task Scheduler هو الجزء الأقل اختبارًا، والملاحظات مرحب بها |

يتوفر الضغط الشفاف على APFS وNTFS. راجع [docs/ARCHITECTURE.md](../ARCHITECTURE.md) لمصفوفة المنصات.
